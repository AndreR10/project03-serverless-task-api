# AWS Cost Estimation

## Overview

This document explains the expected AWS costs for the **Serverless Task Management API**, how the AWS Free Tier applies to this project, and the techniques used to minimize expenses.

The project has been intentionally designed so that normal development and learning activities remain within the AWS Free Tier whenever possible.

---

# Architecture

The application currently consists of the following AWS services:

```text
                 API Gateway
                       │
                       ▼
                 AWS Lambda
                       │
                       ▼
                  DynamoDB
                       │
                       ▼
               CloudWatch Logs
```

Only managed serverless services are used.

There are:

- No EC2 instances
- No load balancers
- No NAT Gateway
- No VPC
- No always-running resources

This significantly reduces operational costs.

# AWS Lambda

## Pricing Model

Lambda charges for:

- Number of requests
- Execution duration
- Memory allocated

Current configuration:

| Setting | Value        |
| ------- | ------------ |
| Runtime | Node.js 24.x |
| Memory  | 128 MB       |
| Timeout | 10 seconds   |

---

## AWS Free Tier

Every month:

- 1,000,000 requests
- 400,000 GB-seconds of compute

For this project, reaching these limits during normal learning is very unlikely.

---

## Cost Optimization

Current optimizations:

- Small memory allocation
- Fast execution
- Lightweight dependencies
- No unnecessary processing

Future improvements:

- Reduce cold starts
- Optimize package size
- Reuse SDK clients

---

# Amazon API Gateway

## Pricing Model

Charges are based on:

- Number of API requests
- Data transferred out

---

## AWS Free Tier

Eligible accounts receive:

- 1,000,000 REST API requests per month (during the Free Tier eligibility period)

Typical development usage remains well below this limit.

---

## Cost Optimization

Current practices:

- Small JSON payloads
- Minimal endpoints
- No unnecessary API calls

---

# Amazon DynamoDB

## Pricing Model

Current billing mode:

```text
On-Demand
```

Charges depend on:

- Read requests
- Write requests
- Data storage

---

## AWS Free Tier

The workload generated by this project is expected to stay comfortably within Free Tier limits for learning purposes.

---

## Cost Optimization

Current choices:

- Small items
- Single table
- On-Demand billing
- No Global Secondary Indexes
- No Streams
- No backups

Future phases may introduce additional features that could affect costs.

---

# Amazon CloudWatch Logs

## Pricing Model

CloudWatch charges for:

- Log ingestion
- Log storage

Current project:

- Small amount of logging
- Low invocation frequency

Expected cost:

Approximately zero during development.

---

## Cost Optimization

Recommended practices:

- Avoid excessive logging
- Do not log entire request bodies unless necessary
- Remove debug logs before production
- Configure log retention (Phase 2)

# What Could Increase Costs?

The following actions may result in charges:

| Activity                                 | Potential Impact               |
| ---------------------------------------- | ------------------------------ |
| Millions of API requests                 | API Gateway and Lambda charges |
| Very large CloudWatch logs               | Increased log storage costs    |
| Large DynamoDB items                     | Higher storage costs           |
| Continuous automated testing             | More Lambda executions         |
| Uploading large files (future S3 module) | Increased storage costs        |

# Free Tier Best Practices

To remain within the Free Tier:

- Use serverless services whenever possible.
- Destroy unused infrastructure.
- Avoid creating duplicate environments.
- Keep Lambda memory allocation low.
- Use On-Demand billing for DynamoDB.
- Limit unnecessary API requests.
- Configure CloudWatch log retention.
- Monitor the Billing Dashboard regularly.

---

# Cost Optimization Checklist

Before leaving the project idle:

- ☐ Run `terraform destroy` if the environment is no longer needed.
- ☐ Remove unused Lambda functions.
- ☐ Delete unused CloudWatch log groups.
- ☐ Delete unused API Gateway stages.
- ☐ Remove orphaned IAM roles and policies.
- ☐ Verify there are no unused DynamoDB tables.

# Key Takeaways

This project demonstrates how modern serverless architectures can provide a fully functional REST API while minimizing operational costs.

By selecting managed AWS services such as Lambda, API Gateway, and DynamoDB, the infrastructure automatically scales with demand and avoids paying for idle resources.

Understanding pricing is an important cloud engineering skill. Designing for cost efficiency from the beginning is considered a best practice and is a common topic in cloud architecture discussions and technical interviews.
